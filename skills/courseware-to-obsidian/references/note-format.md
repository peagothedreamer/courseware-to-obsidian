# Note format (must follow)

## Folder layout

```
<vault>/
└─ <课程>/
   ├─ <课程> 课程总目录.md          # generated by `courseware_tool.py finalize`
   └─ 01-<课件标题>/                # one folder per deck, NN- ordered
      ├─ 01-<课件标题>.md          # folder-note index (same name as folder)
      ├─ 1.1-绪论.md               # one file per section
      ├─ 1.2-....md
      └─ attachments/              # rendered slide images
         └─ <source-stem>_p12.png
```

- Course folder name = what the user calls the course (e.g. `物理化学`).
- Deck folder name = `<NN>-<deck title>`; `NN` is a two-digit order number (`01`, `02`…), assigned from the user's order or filename order. Scan existing `NN-` folders in the course and continue from the highest number. Never use a `lec` prefix for new decks.
- Sanitize the deck title by replacing `\ / : * ? " < > |` with `_` and trimming to 80 chars. If the title is unclear, use the source file stem.
- Section file name = `<number>-<title>.md` (e.g. `1.3-热力学概论.md`), same sanitization, trim to 60 chars.
- Keep the deck's native section numbers (`1.1`, `1.2`, `2.1`…). If the deck has no numbering, assign `1.1`, `1.2`, … in order.
- The deck index file is a **folder note**: `<deck folder>.md`. Never name it `index.md`.
- Existing `lec1-xxx` folders are left untouched; do not migrate them unless the user asks.

## Frontmatter

Section file:

```yaml
---
title: "1.3 热力学概论"
type: knowledge
source: "热力学第一定律.pptx"
tags:
  - 层级/正文
  - 课程/物理化学
---
```

Deck index file:

```yaml
---
title: "热力学第一定律"
type: knowledge
source: "热力学第一定律.pptx"
tags:
  - 课程
  - 层级/目录
  - 课程/物理化学
---
```

Course tag rule: `课程/` + course name with **all whitespace and punctuation removed** (`物理化学（上）` → `课程/物理化学上`). It must match exactly in every file so the graph clusters.

`source` is the original file name (including extension), not the converted PDF name.

## Section body

After the frontmatter, write:

```markdown
# 1.3 热力学概论

### 子主题 A

1~3 句引导，然后立刻用表格/列表展开。

| 项目 | 内容 |
|------|------|
| … | … |

### 子主题 B

行内公式 $Q$、$W$、$\Delta U$；成块公式单独一行：

$$
\Delta U = Q - W
$$
```

Rules, in order of importance:

1. **Only the pages of this section are the source of truth.** Do not invent conclusions the deck did not teach.
2. **No long prose.** Convert everything possible into tables, bullets, numbered steps, or formula blocks.
3. Every internal heading of the deck section becomes one `###` — do not drop one, do not merge unrelated ones.
4. Prefer a table for comparisons, classifications, conditions, or symbol meanings; keep headers clear and rows short.
5. LaTeX only for formulas that actually appear. If a symbol is garbled/missing, use the standard form for that field.
6. Each `###` may start with 1–3 sentences of connective explanation, then structure. Never a wall of text.
7. Use `**bold**` for key terms and at most one callout per notable point:
   - `> [!note] …`
   - `> [!warning] …` for pitfalls
   - `> [!tip] …` for exam tips
   Do not stack callouts.
8. **Wikilinks**: link only to other sections of the same deck/course, at most 4 per section, and only when genuinely related. Always write the full vault-relative path with a readable alias:
   `[[物理化学/01-热力学第一定律/1.4-体积功与可逆过程|1.4 体积功与可逆过程]]`
   Never write bare `[[焓]]` — two courses can both have an `焓` section and the graph would merge them.
9. **Screenshot placeholders**: for example pages, full-page problems, or diagrams that cannot be rebuilt from text, put `【课件截图：第N页】` on its own line after the relevant block. Max 3 per section, page must be inside the section's page range. Ordinary text pages do not get a screenshot. Markdown / plain text sources get no screenshots.
10. Do not output YAML inside the body, do not wrap the note in a code fence, do not add “以下是…” preamble. Body starts at `# <section title>`.
11. **Problems keep their full prompt.** Any example or exercise (including self-tests) from the deck: copy the complete question first — stem, givens, options, data, and question figure — then the solution. Never answer-only or one-line paraphrase. Use a callout for long prompts:
    ```
    > [!example] 例题
    > （完整题干、条件、选项）
    ```
12. **Tables inside callouts need a blank `>` line first.** Without it Obsidian renders raw pipe characters:
    ```
    > [!note] 标题
    > 说明文字
    >
    > | 列1 | 列2 |
    > |-----|-----|
    ```
    Tables outside callouts need no blank line.
13. **Draw what is hard.** For processes, comparisons, and worked calculations, draw a table, code block, ASCII diagram, or LaTeX layout yourself. Screenshots complement the drawing; they do not replace it.

End every section file with navigation:

```markdown
---

← 上一节：[[物理化学/01-热力学第一定律/1.2-热力学基本概念|1.2 热力学基本概念]]　→ 下一节：[[物理化学/01-热力学第一定律/1.4-体积功与可逆过程|1.4 体积功与可逆过程]]
```

Use a full-width space `　` between the two links. Omit a direction when there is no previous/next section.

- **1.2** 热力学基本概念 — [[物理化学/01-热力学第一定律/1.2-热力学基本概念|热力学基本概念]]

*每节含表格/公式/要点与课件截图；节末可跳上一节/下一节。*

```markdown
## 本章小结

- 只写本课件讲过的结论，最多 8 条。
```

Do not add this section by default.

## Exercise note format (type: exercise)

Use this when the user asks for 练习题 / 自测题 / 习题集 / 复习题 — these are the same kind of content. Call the note 「练习题」 and use this single format: a regular section file inside the deck folder (its section number continues the deck's numbering), with the usual navigation footer.

### Frontmatter

```yaml
---
title: "6.5 保角映射练习题（应试版）"
type: exercise
source: "自编·覆盖第六章全部考点"
tags:
  - 层级/练习
  - 课程/复变函数与积分变换
---
```

- `type: exercise`, tag `层级/练习` instead of `层级/正文`.
- `source` = the deck file name when the exercises come from a deck; otherwise state what is covered.

### Body

```markdown
# 6.5 保角映射练习题（应试版）

> 覆盖：<考点 1>、<考点 2>、…、<考点 n>。
> 共 N 题，每题后附折叠答案，先做完再点开。

## 考点地图

| 组 | 考点 | 题号 | 应试形式 |
|----|------|------|----------|
| A | … | A1–A6 | 填空、判断、小证明 |
| B | … | B1–B7 | 填空、选择 |

---

## A 组　<考点>

### A1
<完整题干：条件、选项、题图>

> [!success]- 答案
> <关键步骤；公式用 $...$ / $$...$$>

### A2
…

---

## B 组　<考点>

…

---

## 考前速查

### 标准映射公式

| 原区域 | 目标区域 | 映射 |
|--------|----------|------|
| … | … | … |

### 解题顺序

1. …
2. …

### 易错点

- …

---

← 上一节：[[<课程>/<NN>-<课件>/<上一节>|<上一节标题>]]　→ 下一节：[[<课程>/<NN>-<课件>/<下一节>|<下一节标题>]]
```

Rules:

1. **考点地图 is mandatory.** It lists every group, its problem range, and the exam form. Keep the intro's “共 N 题” and the table in sync whenever problems change.
2. Group headings are `## A 组　<主题>` with one full-width space `　` after `组`. Problems are `### A1`, `### A2`, …; groups go in increasing difficulty, hardest (压轴) last.
3. **Every problem shows the full prompt first** — stem, conditions, options, data. The solution goes in `> [!success]- 答案` so it stays folded until the reader tries.
4. Solutions: key steps, display math, and a short verification (`z=…→…`, boundary/point check) where possible. For true/false items, bold the verdict: `**对**` / `**错**`.
5. Inside a callout, put a blank `>` line before any table, and keep `>` on every math line:
   ```markdown
   > [!success]- 答案
   > 由 …
   > $$w=\frac{az+b}{cz+d}.$$
   ```
6. End every group with `---`; put `---` after the 考点地图 and before the navigation footer.
7. `考前速查` has three subsections: `### 标准映射公式` (table), `### 解题顺序` (numbered list), `### 易错点` (bullets). Keep it within the course's scope.
8. Exercises use the same vault-relative wikilink navigation as section files. If the exercise note is last, end with `→ 返回：[[<课程>/<NN>-<课件>/<NN>-<课件>|本章目录]]`.
9. No screenshots unless a problem depends on a figure that cannot be rebuilt in text.
10. 练习题 and 自测题 are the same thing. Always write a section file with this format; never append a separate exercise/self-test appendix to the deck index.

## Screenshots

`courseware_tool.py render <source> <page> <out.png>` writes the PNG. Use:

```markdown
![课件原图 · 第12页](attachments/热力学第一定律_p12.png)
```

- Put images in the deck folder's `attachments/` subfolder.
- File name: `<source stem>_p<page>.png`; use `-` instead of spaces.
- Render each page once, reuse the path if it appears in several sections.
- For an image source, `render <image> 1 <out.png>` copies the original image.
- If rendering fails (no LibreOffice/Office), delete the placeholder instead of leaving it.

## Source formats

All sources produce the same note structure. Only extraction differs:

| Source | Pages | Screenshots |
|--------|-------|-------------|
| `.pptx` / `.ppt` | slides | yes, after conversion to PDF |
| `.pdf` | PDF pages | yes |
| `.docx` / `.doc` | PDF pages after conversion | yes; without a converter, `.docx` falls back to heading blocks and cannot screenshot |
| `.md` / `.txt` | one page per `#` / `##` heading block | no |
| images | one page per image | read the image with Read; copy it with `render` when needed |

## Self-check before reporting

Run `courseware_tool.py check <course_dir>` and fix every reported problem:

- each deck folder has its folder-note index
- no `【课件截图：…】` / `<!--截图:…-->` left
- every wikilink resolves
- every image reference exists
